## 1. Big O 在回答什么

如果一段程序处理长度为 `n` 的数组，我们关心：当 `n` 从 10 变成 100、1000 时，核心操作次数怎样增长。

| 量级 | `n` 变成 10 倍时 | 常见形状 |
| --- | ---: | --- |
| `O(1)` | 大致不变 | 直接访问一个位置 |
| `O(n)` | 大致变成 10 倍 | 一次完整遍历 |
| `O(n²)` | 大致变成 100 倍 | 两层都随 `n` 变化的循环 |

Big O 不是精确秒数，也不是说 `O(n)` 一定慢。它描述的是**输入规模足够大时的增长趋势**。

## 2. `O(1)`：工作量不随数组长度增加

```java
static int firstOrMinusOne(int[] a) {
    if (a.length == 0) {
        return -1;
    }
    return a[0];
}
```

无论数组长度是 1、100 还是 100 万，这个方法只检查长度并访问第 0 项，操作次数不会随 `n` 增长，所以时间复杂度是 `O(1)`。

注意：`O(1)` 不等于“只执行一行”，而是工作量与 `n` 无关。

## 3. `O(n)`：完整看一遍数组

```java
static int[] sumWithChecks(int[] a) {
    int sum = 0;
    int checks = 0;
    for (int value : a) {
        sum += value;
        checks++;
    }
    return new int[]{sum, checks};
}
```

长度为 `n` 时，循环执行 `n` 次，因此时间复杂度是 `O(n)`。方法只用了固定数量的局部变量；不把返回的两个整数视为随 `n` 增长，所以额外空间是 `O(1)`。

昨天的顺序查找在目标不存在时也要检查全部 `n` 个元素，因此最坏时间复杂度是 `O(n)`。

## 4. `O(n²)`：比较所有不同位置对

```java
static int pairChecks(int[] a) {
    int checks = 0;
    for (int i = 0; i < a.length; i++) {
        for (int j = i + 1; j < a.length; j++) {
            checks++;
        }
    }
    return checks;
}
```

长度为 4 时会比较 6 对；长度为 `n` 时一共比较 `n(n - 1) / 2` 对。把式子展开是 `(n² - n) / 2`，增长最快的是 `n²`，所以记作 `O(n²)`。

不是所有“两层循环”都自动是 `O(n²)`；关键要看每层循环次数是否都随 `n` 增长。

## 5. 常数和低阶项为什么通常省略

下面两个循环依次执行：

```java
for (int value : a) {
    System.out.println(value);
}
for (int value : a) {
    System.out.println(value * 2);
}
```

总操作量大约是 `2n`。当我们只比较增长量级时，`2n` 与 `n` 都随输入线性增长，所以写作 `O(n)`，不是 `O(n²)`。

同理，`3n² + 20n + 1` 的最高增长项是 `n²`，因此写作 `O(n²)`。

## 6. 空间复杂度：额外申请多少空间

```java
static int sum(int[] a) {
    int total = 0;
    for (int value : a) {
        total += value;
    }
    return total;
}
```

这个方法只新增 `total` 和循环变量，额外空间是 `O(1)`。

```java
static int[] copy(int[] a) {
    return java.util.Arrays.copyOf(a, a.length);
}
```

新数组长度随 `n` 增长，因此额外空间是 `O(n)`；复制本身也需要处理 `n` 个元素，时间是 `O(n)`。

## 7. 完整可运行示例

```java
public class ComplexityDemo {
    static int firstOrMinusOne(int[] a) {
        return a.length == 0 ? -1 : a[0];
    }

    static int[] sumWithChecks(int[] a) {
        int sum = 0;
        int checks = 0;
        for (int value : a) {
            sum += value;
            checks++;
        }
        return new int[]{sum, checks};
    }

    static int pairChecks(int[] a) {
        int checks = 0;
        for (int i = 0; i < a.length; i++) {
            for (int j = i + 1; j < a.length; j++) {
                checks++;
            }
        }
        return checks;
    }

    public static void main(String[] args) {
        int[] a = {2, 4, 6, 8};
        int[] result = sumWithChecks(a);
        System.out.println("First: " + firstOrMinusOne(a));
        System.out.println("Sum: " + result[0]);
        System.out.println("Linear checks: " + result[1]);
        System.out.println("Pair checks: " + pairChecks(a));
    }
}
```

输出：

```text
First: 2
Sum: 20
Linear checks: 4
Pair checks: 6
```

<details><summary>查看答案</summary>

在没有排序等额外信息时，任何一个尚未检查的位置都可能存着目标。只有检查全部 `n` 个元素后才能确认不存在，所以最坏时间复杂度是 `O(n)`。

</details>

## ⚠️ 易错点辨析

| 常见误解 | 正确理解 | 修正 |
| --- | --- | --- |
| `O(n)` 表示恰好执行 n 行 | 它描述随输入规模增长的量级 | 数核心操作与循环次数 |
| 两个连续循环是 `O(n²)` | `n + n = 2n`，仍是线性增长 | 写作 `O(n)` |
| 看到两层循环就一定是 `O(n²)` | 要检查每层是否都依赖 `n` | 先写出实际执行次数 |
| `O(1)` 就是瞬间完成 | 常数时间也可能有较大常数 | 只说明不随 `n` 增长 |
| 时间复杂度和空间复杂度是一回事 | 一个看操作增长，一个看额外空间增长 | 分别说明时间和空间 |
| Big O 要保留所有系数 | 常数倍和低阶项不改变主要增长趋势 | `3n² + 20n + 1` 写作 `O(n²)` |

## ✍️ 动手练习

### 练习 1 · 连续循环

两个先后执行、各遍历数组一次的循环，整体是 `O(n)` 还是 `O(n²)`？

<details><summary>查看答案</summary>

是 `O(n)`。总次数约为 `2n`，省略常数倍后仍是线性增长。

</details>

### 练习 2 · 数不同位置对

`n = 5` 时，`for (i = 0; i < n; i++)` 与内部 `for (j = i + 1; j < n; j++)` 一共执行多少次内部操作？

<details><summary>查看答案</summary>

`4 + 3 + 2 + 1 + 0 = 10` 次，也就是 `5 × 4 / 2`。

</details>

### 练习 3 · 时间与空间

复制一个长度为 `n` 的数组到新数组，时间与额外空间分别是什么量级？

<details><summary>查看答案</summary>

需要处理 `n` 个元素，时间为 `O(n)`；新数组保存 `n` 个元素，额外空间为 `O(n)`。

</details>
