## 1. 删除只是左移，不会缩短数组对象

设容量为 6、有效长度 `size = 4`，有效数据为 `[10, 20, 30, 40]`。删除下标 1：

1. 将下标 2 的 30 移到下标 1。
2. 将下标 3 的 40 移到下标 2。
3. 将原有效尾位置下标 3 置 0。
4. 调用者把 `size` 从 4 减到 3。

移动次数为 `size - index - 1 = 4 - 1 - 1 = 2`。物理数组长度仍是 6，只有前 3 项是有效数据。置 0 是本项目的清理约定；**0 本身可以是有效元素，不能用它判断长度。**

## 2. 完整可运行检查

保存为 `DeleteCostCheck.java`，运行 `javac DeleteCostCheck.java`，再运行 `java DeleteCostCheck`。

```java
import java.util.Arrays;

public class DeleteCostCheck {
    // 前提：values 非 null，且 0 <= size <= values.length。
    static int deleteAt(int[] values, int size, int index) {
        if (index < 0 || index >= size) {
            return -1;
        }
        int shifts = 0;
        for (int i = index; i < size - 1; i++) {
            values[i] = values[i + 1];
            shifts++;
        }
        values[size - 1] = 0;
        return shifts;
    }

    public static void main(String[] args) {
        int[] values = {10, 20, 30, 40, 0, 0};
        int size = 4;
        int shifts = deleteAt(values, size, 1);
        if (shifts >= 0) {
            size--;
        }
        System.out.println("Shifts: " + shifts);
        System.out.println("Size: " + size);
        System.out.println("Capacity: " + values.length);
        System.out.println("Physical: " + Arrays.toString(values));
        System.out.println("Logical: " + Arrays.toString(Arrays.copyOf(values, size)));
    }
}
```

预期输出：

```text
Shifts: 2
Size: 3
Capacity: 6
Physical: [10, 30, 40, 0, 0, 0]
Logical: [10, 30, 40]
```

`deleteAt` 里的 `size` 是整数参数的副本。即使在方法里写 `size--`，也不会自动改变 `main` 的变量。因此由 `main` 在确认成功后减 1。数组参数同样复制的是引用，但引用仍指向同一个数组，所以修改数组元素能被调用者看到。

## 3. 0 次移动也是成功

删除最后一项不需要左移，返回 `0`；删除唯一元素也返回 `0`。只有非法位置返回 `-1`。

```java
if (shifts >= 0) {
    size--;
}
```

不能写 `if (shifts > 0)`：否则删尾或删唯一元素时，`size` 不会更新。失败时必须先返回，数组内容和调用者的 `size` 都保持不变。

## 4. 用计数说明复杂度

以下 `n = size`，分析核心方法，不包括打印与用于展示的复制。

| 操作 | 检查或移动次数 | 最好时间 | 最坏时间 | 额外工作空间 |
| --- | --- | --- | --- | --- |
| 顺序查找 | 首项命中 1 次；不存在时 n 次 | O(1) | O(n) | O(1) |
| 有空位时在 index 插入 | n − index 次移动 | 尾插 O(1) | 首插 O(n) | O(1) |
| 在有效 index 删除 | n − index − 1 次移动 | 删尾 O(1) | 删首 O(n) | O(1) |
| 满容量插入或非法位置 | 检查后立即返回 | O(1) | O(1) | O(1) |

“没有移动”不等于时间为 0：仍有条件检查、赋值或返回，只是次数不随 n 增长。

显示逻辑数组时，`Arrays.copyOf(values, size)` 创建了一个长度为 n 的新数组，额外占 O(n) 空间。不能把“核心删除方法额外 O(1)”误说成“包含复制和输出的整个程序额外 O(1)”。输入数组自身占用与容量有关的空间。

## ⚠️ 易错点

| 错误 | 后果 | 修正 |
| --- | --- | --- |
| 删除条件允许 `index == size` | 将空余位置当成真实元素 | 必须 `index < size` |
| 先清零再移动 | 可能丢掉仍需读取的值 | 先左移，最后清理旧尾 |
| 循环到 `i < size` | 读取下标 size，可能越界或读到空余值 | `i < size - 1` |
| `shifts > 0` 才减长度 | 删尾后长度错误 | 判断 `shifts >= 0` |
| 在形参里减 size，以为 main 会改变 | 调用者长度仍是旧值 | 由调用者更新整数变量 |
| 统计程序打印后的耗时来猜复杂度 | I/O 与复制掩盖核心成本 | 分开数核心检查和移动次数 |
